📌 What is RAG?

✦ Retrieval-Augmented Generation

RAG is an architecture that retrieves relevant documents from a knowledge base (vector database) and injects them into the LLM prompt. The LLM then generates answers grounded in retrieved context.

🎯 Why RAG over plain LLM? — LLMs have limited knowledge (cutoff date) and hallucinate. RAG provides real-time, verifiable, domain-specific information. No fine-tuning needed.
💡 Example scenario: Ask "What is our company's refund policy?" → RAG retrieves latest policy PDF chunk → LLM answers accurately with citation.

⚙️ How RAG Works (The Pipeline)

📄 Step 1: Indexing — Chunk documents → Generate embeddings → Store in vector DB.
🔎 Step 2: Retrieval — Embed user query → Find top-k similar chunks (cosine similarity).
🤖 Step 3: Generation — Inject retrieved chunks + user query into LLM prompt → Generate grounded answer.
# Simplified RAG flow pseudo-code query = "What are RAG benefits?" query_embedding = embed(query) chunks = vector_db.search(query_embedding, top_k=3) prompt = f"Context: {chunks}\nQuestion: {query}\nAnswer based on context:" response = llm.generate(prompt)

✦ Build a document Q&A system from scratch
# Install: pip install langchain chromadb openai tiktoken from langchain.document_loaders import TextLoader from langchain.text_splitter import RecursiveCharacterTextSplitter from langchain.embeddings import OpenAIEmbeddings from langchain.vectorstores import Chroma from langchain.chat_models import ChatOpenAI from langchain.chains import RetrievalQA # 1. Load and chunk documents loader = TextLoader("company_policy.txt") documents = loader.load() text_splitter = RecursiveCharacterTextSplitter(chunk_size=500, chunk_overlap=50) chunks = text_splitter.split_documents(documents) # 2. Create vector store (embeddings + Chroma) embeddings = OpenAIEmbeddings() vectorstore = Chroma.from_documents(chunks, embeddings) # 3. Set up RAG chain llm = ChatOpenAI(model="gpt-3.5-turbo", temperature=0) qa_chain = RetrievalQA.from_chain_type( llm=llm, chain_type="stuff", retriever=vectorstore.as_retriever(search_kwargs={"k": 3}) ) # 4. Query response = qa_chain.run("What is the remote work policy?") print(response)

  • Index all internal docs (Notion, Confluence, Google Drive).
  • Chunk and embed with sentence-transformers.

  • Query via Slack bot using GPT-4.
✅ Impact

  • Answers with source citations (increased trust).

📊 RAG Evaluation Metrics

✦ How to measure RAG quality
  • Faithfulness: Does answer contradict retrieved context?
  • Answer Relevance: How well does answer address query?
  • Context Relevancy: Are retrieved chunks actually useful?
🛠️ Tools: RAGAS, TruLens, DeepEval — use LLM-as-judge for automated evaluation.

⚡ Advanced RAG Techniques

✦ Beyond naive RAG
  • HyDE: Generate hypothetical answer, then retrieve.
  • Self-RAG: LLM decides when to retrieve.
  • Re-ranking: Reorder retrieved chunks with cross-encoder.
  • Parent Document Retriever: Retrieve chunks, return larger context.
💡 Where to apply: High-stakes domains (legal, medical) where retrieval accuracy is critical.

✅ RAG Best Practices & Common Pitfalls

👍 Best Practices
  • Use overlapping chunks (preserve context).
  • Include metadata (source, date) in retrieval.
  • Set temperature low (0-0.3) for factual answers.
  • Implement fallback: if low similarity score → say "I don't know".
⚠️ Common Pitfalls
  • Chunks too small → missing context.
  • Outdated embeddings → poor retrieval.
  • No reranking → top results irrelevant.
  • Ignoring token limits → truncation of context.
🧪 Debugging tip: Always inspect retrieved chunks before sending to LLM. Use "trace" logging in LangChain to see what context was used.
