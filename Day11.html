📝 NLP Basics: Bag-of-Words & Word Embeddings

Transforming human language into numerical representations — from sparse vectors to dense semantic spaces.

Day 11 — Natural Language Processing Foundations

📌 Why Convert Text to Vectors?

✦ The core problem

Machine learning models work with numbers, not raw strings. NLP pipelines must encode text into numerical representations that capture meaning, syntax, and semantics.

🎯 Why two approaches (BoW vs Embeddings)? — Bag-of-words is simple and interpretable but loses word order & semantics. Embeddings capture semantic similarity (e.g., "king" ~ "queen") but require more data or pre-trained models.
💡 Example task: Sentiment analysis of movie reviews: "This movie was great, fantastic acting!" → numerical vector → classifier output: positive.

⚙️ The NLP Pipeline Overview

🧩 Typical steps
  • Text preprocessing: Lowercasing, tokenization, stopword removal.
  • Vectorization: BoW, TF-IDF, or Embeddings (Word2Vec, GloVe).
  • Model training: Classifier / regressor / sequence model.
✅ Key trade-off: BoW is fast, sparse, counts words. Embeddings are dense, low-dimensional, capture relationships.

📚 Bag-of-Words (BoW) & TF-IDF

✦ What is BoW?

Creates a vocabulary of all unique words. Each document becomes a vector of word counts (frequency). Ignores grammar and word order.

# Example: two documents doc1 = "the cat sat on the mat" doc2 = "the dog sat on the log" Vocabulary = ["cat", "dog", "mat", "log", "on", "sat", "the"] BoW vectors: doc1 = [1, 0, 1, 0, 1, 1, 2] # "the" appears twice doc2 = [0, 1, 0, 1, 1, 1, 2]
✦ TF-IDF (Term Frequency-Inverse Document Frequency)

Weights words by importance: penalizes common words across documents, boosts rare informative words.

📊 Why TF-IDF better than raw counts? — Reduces impact of stopwords ("the", "and") and highlights distinctive terms.
from sklearn.feature_extraction.text import CountVectorizer, TfidfVectorizer # BoW vectorizer = CountVectorizer() bow = vectorizer.fit_transform(["text corpus here"]) # TF-IDF tfidf = TfidfVectorizer() tfidf_matrix = tfidf.fit_transform(documents)
🎯 Where BoW shines: Spam detection, document classification, topic modeling (LDA), when interpretability matters.

🧠 Word Embeddings: Dense Semantic Vectors

✦ What are embeddings?

Dense, low-dimensional vectors (e.g., 50-300 dimensions) where semantically similar words have similar vector representations. Learned from large text corpora using neural networks (Word2Vec, GloVe, FastText).

📐 king → [0.2, -0.4, 0.7, ...]
queen → [0.21, -0.39, 0.71, ...] (close!)
Semantic analogies: "king - man + woman ≈ queen"
✦ How they capture meaning

Distributional hypothesis: "You shall know a word by the company it keeps." Words appearing in similar contexts have similar meanings.

# Using pre-trained embeddings (GloVe / Word2Vec) import gensim.downloader as api model = api.load("glove-twitter-25") # 25-dim vectors vec = model["apple"] # dense vector similar = model.most_similar("king", topn=3) print(similar) # [('queen', 0.78), ('prince', 0.69), ...]
💡 Why embeddings dominate modern NLP: Capture synonymy, analogy, transfer learning (use pre-trained on millions of docs). Essential for deep learning models (RNNs, Transformers).

📋 Complete Reference: BoW/TF-IDF vs Word Embeddings

FeatureBag-of-Words / TF-IDFWord Embeddings
WhatSparse, high-dimensional count/weight vectorsDense, low-dimensional learned vectors
Why chooseSimple, interpretable, works for small datasetsSemantic similarity, context-aware, transfer learning
How it worksVocabulary lookup, counting or TF-IDF weightingNeural prediction models (CBOW, Skip-gram) or matrix factorization
Where usedTraditional ML (Naive Bayes, SVM), spam filtering, topic modelsDeep learning (RNN, LSTM, BERT), chatbots, machine translation, sentiment analysis
Pro/ConsNo semantics, high-dimensional, order lost. (+) fast, no trainingCaptures meaning, dense, pre-trained available. (-) needs large corpus for training

🚀 Beyond Static Embeddings: Contextualized Representations

Traditional Word2Vec/GloVe produce one vector per word regardless of context. Modern models (ELMo, BERT, GPT) generate dynamic embeddings based on surrounding words.

💡 Example: "bank" in "river bank" vs "money bank" → different vectors. BERT uses attention to encode context.
# Using transformers library (Hugging Face) from transformers import AutoTokenizer, AutoModel import torch tokenizer = AutoTokenizer.from_pretrained("bert-base-uncased") model = AutoModel.from_pretrained("bert-base-uncased") inputs = tokenizer("I love NLP", return_tensors="pt") outputs = model(**inputs) # outputs.last_hidden_state contains contextual embeddings
🌍 Where BERT-style embeddings used: State-of-the-art for question answering, named entity recognition, text classification — virtually every modern NLP system.

🌍 Where BoW & Embeddings Power Real Systems

  • Search Engines: TF-IDF for initial retrieval + embeddings for semantic ranking.
  • Chatbots: Embeddings capture intent similarity (e.g., "book flight" vs "reserve ticket").
  • Recommendation Systems: Document embeddings for content similarity.
  • Healthcare: BoW for clinical notes classification (fast, interpretable).
  • Legal Tech: Embeddings for contract similarity search.

📊 Preprocessing & Best Practices

🔧 Before vectorization
  • Tokenization: split text into words/subwords.
  • Lowercasing (reduces vocabulary size).
  • Stopword removal (optional: "the", "a", "is").
  • Stemming/Lemmatization (reduce to root: "running" → "run").
import nltk from nltk.corpus import stopwords from nltk.stem import PorterStemmer stemmer = PorterStemmer() tokens = ["running", "flies"] stems = [stemmer.stem(t) for t in tokens] # ["run", "fli"]

🧪 Intuition: Embedding Space Analogy

🗺️ Imagine mapping words onto a 2D semantic map:
"king" 👑 → (0.8, 0.2)
"queen" 👸 → (0.79, 0.18)
"apple" 🍎 → (-0.5, 0.9)
Distance in embedding space corresponds to semantic relatedness. BoW would see all words as orthogonal dimensions!
✅ Final advice: Start with TF-IDF + linear model for baseline. If you need semantics or high accuracy, move to pre-trained embeddings (Word2Vec, GloVe, or BERT). For deep learning, always use embeddings as input layer.

🎯 Day 11 Core Takeaways — NLP Vectorization:

✔ Bag-of-Words / TF-IDF: Sparse, interpretable, counts words. Great for baselines and small datasets.
✔ Word Embeddings: Dense vectors capturing semantics, analogies, and similarity. Essential for deep learning.
✔ What: BoW = frequency matrix. Embeddings = learned distributed representations.
✔ Why: Machines need numbers; choices depend on interpretability vs semantic richness.
✔ How: Scikit-learn for BoW/TF-IDF; Gensim, spaCy, or transformers for embeddings.
✔ Where: Sentiment analysis, search, translation, chatbots — every NLP pipeline starts here.

📝 From word counts to semantic vectors — mastering text representation is the first step toward human-like language understanding.
