📊 Evaluation Metrics: Accuracy · Precision · Recall · F1 Score

Master the art of measuring classification performance — when to use which metric and why accuracy can be misleading.

Day 6 — Model Evaluation & Confusion Matrix Deep Dive

🔍 Foundation: The Confusion Matrix

All metrics derive from four fundamental counts based on predictions vs actual labels (binary classification).

Predicted YES
Predicted NO
Actual YES
✅ TP (True Positive)
❌ FN (False Negative)
Actual NO
⚠️ FP (False Positive)
✅ TN (True Negative)
🧠 Why this matters: TP = correct positives, TN = correct negatives, FP = false alarm (Type I error), FN = missed detection (Type II error). Metrics transform these into actionable scores.

🎯 Accuracy

✦ What is it?

Proportion of total correct predictions out of all predictions: (TP + TN) / (TP + TN + FP + FN).

Accuracy = (Correct predictions) / (Total predictions)
🎯 Why & When? — Best when classes are balanced and all errors are equally bad. Simple, intuitive.
📌 Example: Email spam filter with 950 non-spam + 50 spam emails. Model predicts 940 non-spam correctly, 30 spam correctly → Accuracy = (940+30)/1000 = 97%. But if it missed 20 spam emails, accuracy still high — misleading!
from sklearn.metrics import accuracy_score
acc = accuracy_score(y_true, y_pred)

⚠️ Where it fails: Imbalanced datasets (fraud, rare disease). A model predicting "not fraud" for all transactions can have 99.8% accuracy but is useless.

🎯 Precision

✦ What is it?

Of all positive predictions, how many were actually correct? TP / (TP + FP). Answers: "When model says positive, how often is it right?"

Precision = TP / (TP + FP)
🎯 Why use Precision? — Critical when false positives are costly. Spam detection: FP means marking legitimate email as spam (bad!).
📌 Cancer screening: Out of 100 patients flagged as high-risk, only 30 actually have cancer → Precision = 30/100 = 30% (many false alarms). High precision needed to avoid unnecessary stress/operations.
from sklearn.metrics import precision_score
prec = precision_score(y_true, y_pred)

Where it shines: Recommendation systems, search engines (relevant results precision).

📌 Recall (Sensitivity / TPR)

✦ What is it?

Of all actual positives, how many did we correctly capture? TP / (TP + FN). "How sensitive is model to positive class?"

Recall = TP / (TP + FN)
🎯 Why Recall matters? — Critical when missing a positive is expensive (false negatives). Fraud detection: missing fraud = huge loss. Disease detection: missing tumor = fatal.
🚨 Fraud detection: 1000 fraudulent transactions. Model catches 950 → Recall = 950/1000 = 95% (excellent). Even if many false positives (low precision), high recall ensures frauds are flagged.
from sklearn.metrics import recall_score
rec = recall_score(y_true, y_pred)

Where recall dominates: Security threat detection, disaster warning, medical diagnosis.

⚖️ F1 Score

✦ What is it?

Harmonic mean of precision and recall: 2 * (Precision * Recall) / (Precision + Recall). Balances both metrics.

F1 = 2 × (P×R)/(P+R)
🎯 When to use F1? — Imbalanced classes, and you need a single metric that balances false positives & false negatives. Best when both precision and recall are important.
🩺 Rare disease diagnosis: Precision = 80%, Recall = 60% → F1 = 2*(0.8*0.6)/(1.4) ≈ 0.686. F1 penalizes extreme imbalances unlike accuracy.
from sklearn.metrics import f1_score
f1 = f1_score(y_true, y_pred)

Where F1 shines: Document classification, customer churn prediction, models where you need trade-off interpretation.

🔎 Case Study: Credit Card Fraud Detection — choosing the right metric

Dataset: 100,000 transactions, 0.2% fraudulent (200 frauds). Model A predicts no fraud at all → Accuracy = 99.8% (terrible for business). Model B catches 170 frauds but has 500 false alarms.

📊 Metrics for Model B:
  • Accuracy = (99,500 + 170)/100,000 ≈ 99.67% (still high but misleading)
  • Precision = 170 / (170+500) = 25.4% → many false alarms
  • Recall = 170/200 = 85% → catches most frauds ✅
  • F1 = 2*(0.254*0.85)/(0.254+0.85) ≈ 0.39 (low due to precision)
🎯 Which metric to prioritize?

Business decision: Missing fraud (low recall) costs heavy chargebacks → recall critical. But too many false positives (low precision) annoy customers. F1 helps balance. Typically fraud teams use recall@k% precision.

# Sklearn evaluation report for imbalanced case
from sklearn.metrics import classification_report
print(classification_report(y_true, y_pred, target_names=['Legit','Fraud']))
💡 Key lesson: Never rely solely on accuracy for imbalanced data. Precision, recall, and F1 give a truthful picture.

⚖️ Precision vs Recall Trade-Off (and how to handle)

Adjusting classification threshold changes trade-off: Higher threshold → higher precision, lower recall. Lower threshold → higher recall, lower precision. F1 score finds sweet spot.

📌 Example: Logistic regression outputs probabilities. By default threshold=0.5. Lower to 0.3 → more positives, recall rises but precision drops. Use Precision-Recall curve to choose optimal threshold.
# Adjust threshold for logistic regression
y_scores = lr.predict_proba(X_test)[:,1]
y_pred_custom = (y_scores > 0.3).astype(int) # increase recall
🎯 F1-beta score gives more weight to recall (beta >1) or precision (beta <1). For fraud detection, F2 (recall-focused) might be better.

🌐 Beyond Binary: Multi-class Metrics

For 3+ classes, we can compute micro-averaging (aggregate TP, FP, FN globally) or macro-averaging (average per-class metrics).

📌 Micro-average F1

Suitable when class imbalance exists, favors majority class.

📌 Macro-average F1

Gives equal weight to each class, better for balanced evaluation.

from sklearn.metrics import f1_score
f1_macro = f1_score(y_true, y_pred, average='macro')
f1_micro = f1_score(y_true, y_pred, average='micro')

Where used: Image classification (10 classes), news topic labeling, species recognition.

📌 Day 6 Core Takeaways — Choose your metric wisely:

✔ Accuracy works only for balanced classes and equal error costs.
✔ Precision minimizes false alarms → use when FP cost high.
✔ Recall minimizes missed detections → use when FN cost high.
✔ F1 Score balances both → single metric for imbalanced data.
✔ Always look at confusion matrix, never trust a single metric blindly.
✔ Where to apply: Every classification project — from healthcare to finance to NLP.

📈 Evaluation metrics are the compass of ML: Accuracy, Precision, Recall, F1. Master them to build trustworthy, robust models.
